## Что добавлено и исправлено по сравнению с исходным PDF

1. **13 зондов вместо 7.** Добавлены: отсутствие `Mcp-Method`, отсутствие `Mcp-Name`, расхождение
   версии в заголовке и `_meta`, `tasks/list`, legacy follow-up после `initialize`, медленный
   инструмент. У всех — точные HTTP-статусы и коды.
2. **Эксперимент A перемерян.** 5 повторов на ячейку, медианы: 4/16/63 хода против 2/3/8,
   выигрыш 2,0× / 5,3× / 7,9×. Добавлена оценка роста контекста (O(N²), ~428 КБ против ~7,4 КБ).
   Объяснено расхождение с идеализированными 61/15/3.
3. **Эксперимент B расширен с 3 до 6 вариантов.** Добавлены внешний воркер, recovery с
   идемпотентностью и recovery без неё. Последний показывает двойной побочный эффект (2/2).
   По ходу пришлось убрать три гонки в самом стенде: момент убийства, фиксированную паузу вместо
   поллинга и boot scan, который не дожидался протухания heartbeat. Без этого таблица не
   воспроизводилась.
4. **Rust переведён из «не проверяли» в «готов».** `rmcp` 3.11.0 реализует Tasks: `TaskManager`,
   `CreateTaskResult`, `tasks/get/update/cancel`, примеры. Это второй серверный рантайм после C#.
5. **Python уточнён.** Есть инфраструктура расширений (`MethodBinding`), но нет самого Tasks;
   `tasks/update` и `tasks/cancel` отсутствуют. В таблице это сформулировано как «0 упоминаний
   extension id плюс есть `MethodBinding`» — чтобы не путать каркас с готовым рантаймом.
6. **C# уточнён.** По умолчанию `ExecutionModeSelector` = `Optional` для всех инструментов,
   работа выполняется в фоне в том же процессе (XML-документация `IMcpTaskStore`), режимы
   `Synchronous`/`Optional`/`Required`, интерфейс `IMcpTaskStore`.
7. **ptai-mcp обновлён.** Добавлено явное `persistence: 'current_process_only'`, уточнено, что SDK
   1.32.2 лежит в `devDependencies` и попадает в сборку через tsup.
8. **Раздел «Что в прод»** расширен строками про внешнее хранилище без heartbeat и про внешний
   воркер с lease/идемпотентностью.
9. **Добавлен чек-лист прода** и раздел «Как воспроизвести».
10. **Ссылки на источники** дополнены Rust SDK и SEP-2663; версии C# и Rust сверены по NuGet и
    crates.io.
11. **Добавлены живые прогоны Go, C#, Rust и Java.** Go: клиент+сервер на `go-sdk` 1.8.0, версия
    `2026-07-28`, Tasks в API нет. C#: сервер с `WithTasks` и клиент с поллингом, 12/12 задач,
    поллинг ~2,1 с при инструменте 1,5 с. Rust: примеры `rmcp` 3.11.0 с `CreateTaskResult`.
    Java: клиент+сервер на `io.modelcontextprotocol.sdk:mcp` 2.2.0, версия `2026-07-28`,
    `extensions: null`, Tasks нет (0 вхождений extension id в трёх jar’ах).
12. **Добавлена обложка** `cover.png` 1200×630, нарисована кодом.

## Ограничения, которые лучше не скрывать

- Клиенты не тестировались: только публикации Upstash/Upsy и трекеры.
- Java запущена живьём (JDK 21 + Maven 3.10.2), но проверено только modern-ядро: расширений Tasks
  в 2.2.0 нет. Go, C#, Rust и Java — настоящие прогоны.
- «Модель» в эксперименте A — детерминированный цикл, а не LLM.
- Песочница Windows: `taskkill` и старт процесса медленные, поэтому в вариантах 1–2 статус не становится
  терминальным и поллинг упирается в таймаут 10 с. Это указано в статье и не влияет на выводы.
